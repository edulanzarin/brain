# Estética é por projeto, princípio de design é que se reusa

> Não dá pra ter um visual só que sirva pra todo sistema. O que viaja entre projetos
> é o **princípio** (como a tela se organiza), não a **cara**. Cada sistema escolhe a
> própria estética.

## O pensamento

Um dashboard denso, uma landing, um app de cliente e um mobile não compartilham
linguagem visual — cada forma pede uma cara. Tratar um único sistema visual como
"reutilizável entre projetos" força a estética de um tipo de produto em cima de todos
os outros, e é aí que não cabe.

O que de fato viaja é a camada de princípio: token semântico em vez de valor literal,
escala fechada, hierarquia por superfície, todo estado da tela tem visual, estado
compartilhável mora na URL. Esses continuam verdade trocando a cara inteira. Já o
dialeto "Aurora Glass" — sidebar em acordeão, vidro flutuante, tema do dashboard — é
o **meu gosto pra sistema de trabalho**, uma opção entre várias, não lei. Casa com
[[Interface enxuta e compacta, sem desperdício de espaço]], que também trata o glass
como preferência, não como universal.

## Por que importa

É a regra "primeiro a base" aplicada ao design: puxar o aprendizado pro nível mais
primitivo em que ele ainda seja verdade — e isso é o princípio, não o CSS. Ver
[[Camadas do conhecimento - princípio, padrão, aplicação]]. Uma estética compartilhada
empurrada pra todo projeto é conhecimento preso na altitude errada, o vício que
[[Conhecimento pertence à base, não ao projeto]] existe pra evitar.

Na prática muda como o [[Design]] se apresenta: o reutilizável é a base; as técnicas
de lá são um dialeto de dashboard que um projeto herda só se for da mesma forma.
